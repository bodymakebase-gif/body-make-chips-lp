# レビュワー用クーポン

管理画面の「クーポン」で、3袋を無料にするコードを発行・停止できる。

1. コード（例 `Reviewer00`）、同梱するアンケート名（例 `アンケート00`）、利用上限を入力して発行する。
2. モニターにはLPからお試し3袋を選び、Stripeの画面でコードを入力してもらう。3袋は税込・送料込み0円。カード入力は不要だが、配送先・連絡先・販売条件の確認は必要。
3. 注文・発送画面に「レビュワー用・無料」、使用コード、同梱アンケート名が表示される。発送確認欄にも同梱物が入る。
4. 不要なコードは停止する。停止しても確定済み注文やアンケートの履歴は変わらない。

`Reviewer01`など別コードを作り、別のアンケート名を指定すると、同梱物を分けられる。アンケート名から紙を自動作成・印刷する機能はない。

利用上限はコード全体の注文数で、1人あたりの制限ではない。個別配布には、相手ごとに異なるコードを上限1回で発行する。個人情報をコードやアンケート名に含めない。

既存のコードは停止後も同じ文字列で再発行しない。アンケート名や上限を変える場合も新しいコードを発行する。通信結果が不明な場合は「発行結果を確認する」「停止結果を確認する」を使い、同じ登録番号で再確認する。

## 運用・連携

- Stripe Couponはお試し3袋のProductだけに100%OFF、1回の注文に適用。10袋・30袋は対象外。本番3つのPriceが別Productであることは2026-11-26に確認した。
- 管理用StripeキーにはPrices読取・Coupons読取/書込・Promotion Codes読取/書込が必要。Checkoutの照合でもCouponsとPromotion Codesの読取が必要。秘密値はCloudflare Secretsのみへ保存し、コード・Git・公開画面・ログには置かない。
- 配送の正本は署名検証済みWebhookとStripeからの再取得。完了ページは注文確定や在庫操作を行わない。
- 無料注文は0円・100%割引・3袋の価格と商品・適用コードの管理者メタデータを確認する。`paid`または0円の`no_payment_required`で、Sessionがcompleteのときのみ確定。
- 定価は`reservations.amount`、実請求額は`amount_total`、割引額は`amount_discount`。使用コードとアンケート名は注文確定時に保存し、その後のStripeメタデータ変更で書き換えない。
- 新規予約だけ`checkout_version=2`。既存予約はversion1のまま、Stripeの再送パラメータを保持。既存の予約・在庫・発送履歴をリセットしない。
- 無料提供はGA4のpurchaseから除外する。正の割引購入は実請求額を送る。在庫の「注文確定」は無料提供分も含む袋数で、発送登録で再減算しない。
- 自動テストに加え、既存Stripeサンドボックス+専用ローカルDBでコード発行→100%適用→カードなし0円完了→注文表示→発送→コード停止を確認。本番にはテスト注文を作らない。
